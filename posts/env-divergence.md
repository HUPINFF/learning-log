# 本地跑通 ≠ 线上跑通：环境差异排查手册

> 创建 2026-10-11 ｜ 素材来自 learning-log 项目部署排查
> 用途：以后遇到「本地好好的，线上就是不行」时，回来翻这个。

---

## 0. 只记一句话

> **「在我机器上能跑」不是证据。**
> **真相只存在于目标环境里，不在你的终端里。**

这类问题不会让你显得聪明，只会让你卡住 —— 它不产出任何东西，纯粹是消耗。
所以目标**不是"学会排查"，是"让它别发生"**（见第 4 节，成本 10 秒）。

---

## 1. 两个真实案例

### 案例 A：换行符 —— 两台机器读到的源文件本来就不一样

**现象**
本地 `npm run build` 产出 `index-D64VYN3c.js`（141778 字节），
CI 产出 `index-C9y5PvYt.js`（141772 字节）。
文件名不同 → 本地预览好好的，线上 404。

**排查**

```powershell
git ls-files --eol                          # 找 i/ 和 w/ 不一致的文件
git cat-file -s HEAD:about.md               # 仓库里那版多少字节
(Get-Item about.md).Length                  # 磁盘上那版多少字节
git diff                                    # 无输出
```

结果：

```
i/lf  w/crlf  attr/text=auto eol=lf  about.md
仓库 572 字节 / 磁盘 575 字节 / 差 3 字节
git diff 无输出 —— git 认为它们「完全一样」
```

**根因**（关键，别记错）

不是"Linux 构建导致不一致"。是**同一份文件在你这台机器上就有两个版本**：

| | 从哪来 | 谁在读 |
|---|---|---|
| **磁盘版**（CRLF，575B） | 编辑器直接写到磁盘的 | 你本地 `npm run build` |
| **仓库版**（LF，572B） | `git add` 时按 `.gitattributes` 誊抄的 | CI 的 `actions/checkout` |

`git add` **只誊抄进仓库，不改你磁盘上那份**。
CI 那台机器上没有你的磁盘版，它只有仓库版 —— 所以两边输入不同，输出就不同。

**最阴的地方**：`git diff` 认为这两份是同一个文件，不报差异、不提醒你。
**git 把这个坑藏起来了。**

**为什么只有 `about.md` 中招**
项目里 2 个文件是 CRLF（`about.md`、`MainLayout.vue`），但只有 `about.md` 改变了产物。
因为它走 `?raw` 导入（原样读字节），而 `.vue` 走 Vue 编译器（编译器会规范化换行符）。
→ 判据：**这个文件是「原样读入」还是「过编译器」？**

**修法**

```powershell
git rm --cached <文件>            # 从暂存区踢出，磁盘文件不动
git checkout HEAD -- <文件>       # 重新检出，这次按 .gitattributes 写成 LF
```

跑完 `git ls-files --eol` 应变成 `i/lf w/lf`，且 `git status` **依然干净** ——
因为 git 本来就认为两份一样，不会让你提交任何东西。

**为什么源文件差 3 字节，产物却差 6 字节**
每个 CR 进了 JS 字符串字面量会被转义成 `\` 和 `r` 两个字符。3 × 2 = 6。
同一个原因，两个尺度。

### 案例 B：DNS 劫持 —— 你测的根本不是线上

**现象**
浏览器访问 `xxx.vercel.app` 返回 **403**。怀疑站点坏了。

**排查**

```powershell
Resolve-DnsName xxx.vercel.app    # → 返回 127.0.0.1 ← 这就是答案
curl.exe -o NUL -w "%{http_code} %{time_total}" https://xxx.vercel.app
                                  # → 000，耗时 0.01 秒
```

**根因**

本机的 **Watt Toolkit（原 Steam++）** 监听 `0.0.0.0:80` 和 `0.0.0.0:443`，
把 `github.com` / `*.github.io` / `*.vercel.app` 的 DNS **劫持到 `127.0.0.1`**，
再由它转发到海外节点。于是：

- 你请求的"线上"，实际经过了你本机的代理
- 目标服务器看到的是机房 IP，直接 `403` + `X-Vercel-Mitigated: deny`
- **站点本身完全正常** —— 从 8 个国家的节点访问全是 `200 OK`

**识别特征**

- `Resolve-DnsName <域名>` 返回 `127.0.0.1`
- 响应头多出 `Server: Vercel,WattToolkit`
- 命令行工具**瞬间**失败（0.01–0.1 秒），而浏览器正常
- 关窗口不算关 —— **要完全退出进程**（80/443 还占着）

**关键手法：绕开本机去测**

用第三方多节点服务，从境外节点测目标站点，这样你的机器完全不参与：

```
https://check-host.net/check-http?host=<URL编码后的地址>&max_nodes=5
```

轮询 `/check-result/<request_id>`。每个节点返回的是**数组的数组**，
`$res.<node>[0][3]` 是 HTTP 状态码，`[0][4]` 是 IP。

**教训**：你以为你在测线上，其实你在测你自己的机器。

## 2. 同一类坑的完整清单

| 差异来源 | 你本机 | 目标环境 | 症状 |
|---|---|---|---|
| 换行符 | CRLF | LF | 产物哈希不同 / diff 全红 |
| **文件名大小写** | 不敏感 | **敏感** | `Module not found` |
| **环境变量** | 有 `.env` | **没有** | 本地正常，线上白屏 |
| 依赖服务 | 本地 MySQL 开着 | 没有 | 连不上 |
| 时区 | UTC+8 | UTC | 日期差一天 |
| 网络 | 你能访问的 API | 被墙 / 要走代理 | 请求超时 |
| 并发 | 你一个人点 | 多实例 | 竞态、偶现 |
| 依赖版本 | 没锁死时各装各的 | 同左 | 行为不一致 |
| 绝对路径 | `D:\...` | 不存在 | 构建或运行时报错 |
| 隐藏文件 | `.env` / 本地配置 | 不在 git 里就没有 | 行为不同 |
| **DNS / 代理** | 被本机软件改写 | 真实 DNS | 你测的不是真的 |

**其中能直接把构建搞炸的**：文件名大小写、环境变量、绝对路径。
**注意**：后面每一条都比换行符难查十倍，而且**报错信息基本是误导的** ——
它会把你引到一个完全无关的地方。

## 3. 排查流程（遇到时按这个走）

1. **先问一句**：我本地有什么，目标环境没有什么？
2. **别信本地**。去 CI / 服务器上看真实报错，而不是复现本地的猜想。
3. **确认你测的是真环境**。DNS 有没有被劫持？是不是走了代理？（案例 B）
4. **逐字节对比**，不要靠眼睛。
   - 比文件：`git ls-files --eol`、`git cat-file -s HEAD:<file>`
   - 比产物：文件名 + 字节数，逐个对
5. **找"原样读入"的路径**。过编译器的会被规范化，原样读的不会。
6. **隔离变量**：一次只改一个，改完立刻验证。

---

## 4. 预防（成本 10 秒，收益一劳永逸）

**每一个新项目的第一天**，在根目录放 `.editorconfig`：

```ini
root = true

[*]
end_of_line = lf
charset = utf-8
insert_final_newline = true
trim_trailing_whitespace = true
```

并在 `.gitattributes` 里写：

```
* text=auto eol=lf
```

`.gitattributes` 只管「进仓库的那份」，管不到「编辑器怎么写磁盘」——
**中间这道缝就是案例 A 的坑**。两个都要有。

**VSCode 用户**（不用装插件）：设置里加一行

```json
"files.eol": "\n"
```

> 更本质的做法：**用 WSL 或 Mac 开发**。这一层差异直接不存在。

---

## 5. 判断标准

> 改完 → push → **去看 CI 绿没绿**。绿了才算数。

不是"我本地跑通了"，不是"我觉得应该没问题"。

这也是 CI 存在的根本理由 —— 它不只是"帮你 build"，
是**给你一个和线上一样的、可重复的真相来源**。

---

## 6. 一句话总结

CRLF 只是这类坑里**最无害**的一种表现。
真正会跟你一辈子的是那个心态：

> **永远用目标环境的话说，别用你终端的话说。**
