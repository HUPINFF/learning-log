## 为什么要异步编程，什么是异步

- 也不是说只有 Python 要异步，开发类工程都需要异步操作。客户端发请求，总不能把所有用户的请求一个一个处理完再返回，纯同步太影响性能了。

- **异步**：A 用户发起网络请求，**发送请求很快，等返回很慢**。如果任务队列里还有其他任务，线程在这段等待时间里就不空转 —— 转去执行别的异步操作，比如处理 B 用户的请求、为 B 发起它需要的网络请求。B 的请求返回之前，线程再看还有没有其他任务，有就继续上面的流程。**异步省下的，就是这一个一个等待返回的时间。**

- 一个前提要注意：**队列里得先有别的任务**，线程交出去才有活干 —— 把任务塞进队列的正是 `create_task` / `gather`。

另外注意：Python 和 JS 的异步操作都是**单线程**的。

```python
answers = await asyncio.gather(ask("A"), ask("B"), ask("C"))
print(answers)
```

这里我们把三个 ask 请求一次性推进了任务队列。注意这是**并发**，不是**并行** —— 并行要多线程、多 CPU 核，多个任务真正同时执行；并发只需单线程、单核 CPU，一个线程轮流跑多个任务。

具体到这段代码：发起 `ask("A")` 后、等它返回的过程中，线程去发起了 `ask("B")` 的请求。如果是同步，等待期间线程不会去跑 B、C，只会干等。


## Python 异步编程的实现

```python
async def main():
    t1 = asyncio.create_task(ask("A"))
    t2 = asyncio.create_task(ask("B"))
    await asyncio.gather(t1, t2)   # A 等的时候，线程在跑 B

asyncio.run(main())
```

### async / await 的作用

- `async` 写在函数 `def` 的前面。

- `await` 的作用：**把执行权交还给调度员（事件循环）**，让线程去跑队列里其他就绪的任务；等它指明的那件事做完，当前协程才从原地接着往下跑。
  - 修正一处：不是 `await` 自己"查看有没有任务" —— 查看是**调度员**干的，`await` 只负责撒手。
  - 前提：队列里得先有别的任务（提前用 `create_task` / `gather` 塞进去）。否则线程交出去也没人跑，还是干等 —— 这时候异步和同步没区别。

- 换句话说：执行中一旦遇到"不用 CPU 的等待"（等 I/O、等 sleep），`await` 就把线程交出去，拿它在等 I/O 的空档里跑别的任务。


### Python事件循环

┌─ 走一段同步代码 ──────────────┐
│                              │
└─ 撞到 await → 让出线程 ──────┤
        ↓                     │
   调度员去跑队列里的任务         │
        ↓                     │
   await 指定的那个完成          │
        ↓                     │
   线程回来 ←───────────────────┘
        ↓
┌─ 继续走下面的同步代码 ─────────┐
│                              │
└─ 又撞到 await → 又让出 ... ───┘

一句话：**不是"同步全走完 → 然后异步"，是"走一段同步 → 让出 → 回来 → 再走一段"，交织往复。**
而且队列里的任务不是自动执行的，是被 `await` 让出的空档"捡"起来跑的 —— 一个 `await` 都没有，它们一个都不会跑。

### 没写 await 会怎样

这是个重点。`create_task` / `gather` 只负责**登记** —— 把任务排进队列，**它们自己不会让任务跑起来**；**只有 `await` 会把任务真正驱动起来**。

所以那些**全程没被 await 过**的任务，在 main 跑完之后还没轮到执行。事件循环收尾时会转**最后一圈**，让队列里的任务**各跑一步**：

- 跑得完的（内部没有 await）→ 侥幸活下来
- 跑不完的（内部有 await）→ 卡在半路，被取消

举个例子：

```python
import asyncio

async def fn():
    print('fn')
    await asyncio.sleep(1)      # ← 内部有暂停点
    print('fn结束')

async def main():
    t = asyncio.gather(fn())    # 登记了，但全程没 await

asyncio.run(main())
```

实际输出：

```
fn
_GatheringFuture exception was never retrieved
future: <_GatheringFuture finished exception=CancelledError()>
...
asyncio.exceptions.CancelledError
```

`fn` 打印了 —— 它在收尾那一圈里抢到了一步。但 `fn结束` 没出现：它卡在 `await asyncio.sleep(1)` 上，循环关门，直接被 cancel 了。

**最后那几行是 Python 在报账**：`gather` 返回的那张"取货单"从头到尾没人来取，上面还挂着一个 `CancelledError`，所以它要吼一声。**这行警告就是"没写 await"的书面证据。**

只要补上 `await t`，输出就干净了：`fn` / `fn结束` / 结果，没有截断，也没有警告。

## Python 异步和前端 JavaScript 的对照

学之前我一直拿 JS 的直觉往 Python 上套，踩了不少坑。整理一份对照表：

| 干什么 | JavaScript | Python |
|---|---|---|
| 定义异步函数 | `async function f() {}` | `async def f():` |
| 等待 | `await` | `await` ← **完全一样** |
| 被等的东西 | Promise | 协程（coroutine）/ Task |
| 并发跑一批、收集结果 | `Promise.all([a, b, c])` | `asyncio.gather(a, b, c)` |
| 失败也不中断 | `Promise.allSettled([...])` | `gather(..., return_exceptions=True)` |
| 谁先回来用谁 | `Promise.race([...])` | `asyncio.wait(..., return_when=FIRST_COMPLETED)` |
| 立刻派活、不等 | `const p = f()` | `t = asyncio.create_task(f())` |
| 延时 | `setTimeout(fn, 300)` | `await asyncio.sleep(0.3)` |
| 取消 | 做不到 | `t.cancel()` |
| 事件循环 | 浏览器 / Node 自带 | 要自己写 `asyncio.run(main())` |

**四个最容易踩的坑：**

1. **调用 ≠ 执行**。JS 里 `f()` 会立刻跑到第一个 `await` 才停；Python 里 `f()` **一行都不跑**，只是得到一个协程对象。
   想让它跑：直接 `await`（当场驱动），或者 `create_task` / `gather` 先把它**登记**进队列，再由后面某个 `await` 来驱动 —— 驱动它的不一定是"它自己的" await。
2. **`gather` 要加 `*`**。JS 是 `Promise.all(tasks)` 传数组；Python 是 `gather(*tasks)`，把列表散开。
3. **sleep 单位差 1000 倍**。JS 是毫秒，Python 是秒。
4. **没有 `.then()` 链**。Python 只有 `await`，错误处理用 `try / except`。


## 复习前端 JS 的异步

顺手校正了一个我一直搞反的点：

**`.then()` 不是语法糖 —— 它才是本体；`async/await` 才是 `.then()` 的语法糖。**

```js
async function f() {
  const r = await g();        // 这行会被 Babel 编译成 ↓
}

function f() {
  return g().then(r => {      // 本质就是 .then
    ...
  });
}
```

三层结构：`async/await`（语法糖）→ `.then()/.catch()`（原生方法）→ Promise 对象（数据结构）。

**`.then()` 和 `await` 的功能差别：**

```js
// .then()：挂个回调就走，当前函数不用是 async，也不停
p.then(r => console.log("稍后处理", r));
console.log("立刻执行");        // ← 先打印这个

// await：必须停在原地等
const r = await p;
console.log("等完了才到这");    // ← 一定在后
```

`.then()` 是**订阅**（到点你来叫我），`await` 是**蹲守**（我站这不动）。这跟 Python 里"有没有 `await` 决定让不让位"是同一件事。
