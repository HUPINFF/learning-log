## Token(JWT)的生成，share_token的概念和使用场景(红字片段)


JWT的 编码器，将一串原始二进制（bytes）变成能安全塞进URL的字符串
```python
def b64url(raw:bytes) -> str:
  return base64.urlsafe_b64encode(raw).decode().rstrip("=")
```
我们这里为啥用的是urlsafe_b64encode,而不是用普通的b64encode

是为了生成的JWT我们最后不管放哪都别导致出问题，URL是JWT存放的容器之一，但是URL是最不推荐放JWT，因为容易被泄露，，所以我们这里的urlsafe_b64encode()是为了哪些注定要存进URL的来设计准备的，哪些一般存进URL呢，就是分享token(share_token)不是Token(jwt)了，就是不用登录态也能访问后端拿取数据，share_token和JWT不一样，share_token要存进服务器，随时能使之失效(用户后悔分享)，应用场景：用户想分享给朋友我们job-agnet的查询结果，点击了分享按钮前端显示一个分享链接"http://127.0.0.1:8000/share?t={token}",这个t（token）就是那个share_token，朋友点击后，朋友浏览器向我们后端发起这个"分享"请求，我们后端专门做了一个接口来处理这种没有登录就拿取数据的，我们后端根据URL中的t来查库获取数据，库中存有这个share_token的是否有效的字段

这里我们的share_token为什么放URL呢，目的是：为了把这个share_token发出去给朋友，让朋友拿到能取请求我们后端；分享时只能发送一串文字，一串文字只能是URL了，如果发Authorization ，这个没法放进链接里发出去


### JWT的生成返回函数

```python
def create_token(user:dict) -> str:
  header = {"alg":"HS256","typ":"JWT"}
  payload = {
    "user_id" : user["id"],
    "role" : user["role"],
    "exp" : int(time.time()) + 3600
  }

  h = b64url(json.dumps(header,separators=(",",":")).encode())
  p = b64url(json.dumps(payload , separators=(",",":")).encode())
  sig = hmac.new(SECRET.encode(),f"{h}.{p}".encode() , hashlib.sha256).digest()
  return f"{h}.{p}.{b64url(sig)}"
```


## 什么时候GET,什么时候POST

按这个来判断就行了:
① 会改变服务器的数据吗？
     不会  →  基本是 GET（接着看 ②）
     会    →  POST / PUT / PATCH / DELETE（接着看 ③）

② 有东西不能进 URL 吗？（密码、身份证号、几千字的长条件）
     有    →  只能 POST   ← /login 就是被这条踢到 POST 的
     没有  →  GET

③ 造新的 / 整体替换 / 改局部 / 删掉？
     →  POST / PUT / PATCH / DELETE

一条提示：
GET会缓存，POST不会
浏览器 / CDN / 反向代理 会缓存 GET 的响应
→ 第二次访问同一个 /jobs?region=北京，可能压根不发请求，直接吃缓存
POST 默认不缓存

## 第五种参数cred = Depends(HTTPBearer())

HTTPBearer()函数被调用：
```python
async def __call__(self, request: Request):
    auth = request.headers.get("Authorization")          # ① 去请求头里找
    if not auth:                                          # ② 根本没有 → 抛401，没有登录
        raise HTTPException(401, "Not authenticated",
                            headers={"WWW-Authenticate": "Bearer"})

    scheme, _, param = auth.partition(" ")                # ③ 切开 "Bearer eyJ..."
    if scheme.lower() != "bearer":                        # ④ 格式不对 → 抛
        raise HTTPException(403, "Invalid authentication credentials")

    return HTTPAuthorizationCredentials(                  # ⑤ 都好 → 返回对象
        scheme=scheme,
        credentials=param,                                #    前缀已剥掉
    )

```

这里会在接口函数执行前会执行HTTPBearer()这个依赖函数，这个依赖函数会保证该请求也没有Token，没有就401返回

### 一、原来本机早就装着 MySQL 8.0，而且一直开着

本来以为要自己动手装一套数据库，查了一下本机的进程和服务：

```powershell
Get-Process mysqld                    # 有个 PID，但 Path 那列是空的
Get-CimInstance Win32_Service -Filter "Name='MySQL80'"
```

查出来一个 Windows **服务**叫 `MySQL80`。`Path` 空是因为**服务进程以 SYSTEM 身份运行**，普通权限看不到路径，得用 `Win32_Service` 拿 `PathName`。

**"服务"这个概念今天才真懂**：它不是 XAMPP 里的东西，而是**一个由 Windows 托管、开机自动启动的程序**。所以我根本不用手动去"启动 MySQL"，它从我装机那天起就一直在跑。

顺带把目录名搞清楚了：`bin` = 程序(二进制可执行文件存放地)，`data` = 数据，`my.ini` = 配置，`mysqld` 的 `d` = daemon（守护进程），就是服务端进程程序。


### 二、"mysql" 一个词指四个东西

这是所有混乱的根源，必须分清：

| 说"mysql"的时候，可能指 | 它是什么 |
| --- | --- |
| MySQL | 产品名 |
| `mysqld` | **服务端进程** —— 真正存数据、算查询的那个 |
| `mysql.exe` | **命令行客户端** —— 只是一个连过去的窗口 |
| `mysql`（库名） | MySQL 内部的**系统库**，存用户、密码、权限 |

客户端-服务端我这么理解：**`mysql.exe` 是电话机，`mysqld` 是接电话的那头。电话机本身不存任何数据。**

数据最终是 `data\` 目录下的**一个个文件夹，一个文件夹一个库**。所以重启电脑数据还在 —— 它本来就是磁盘上的文件。

内置的系统库有四个，永远别删：`information_schema`（元数据字典）、`mysql`（用户+权限）、`performance_schema`、`sys`。

### 四、建表时的设计决定（都是被真实数据逼出来的）

**1. 为什么 `jobs` 里有两个 ID？**

- `job_id INT AUTO_INCREMENT PRIMARY KEY` —— **代理主键**，数据库自己发的号，对外没意义，只用来被别的表引用
- `source_job_id BIGINT NOT NULL UNIQUE` —— **外部身份**，scraper 抓来的原始 ID。加 `UNIQUE` 是为了**脚本可以重复跑**：同样的数据灌第二遍时能认出"这条已经有了"，不会重复插入

**2. 为什么 `salary_max` 可以是 `NULL`？**

946 行里有 **307 行（32%）的薪资是"10000元以上"**，根本没有上限。设成 `NOT NULL` 的话，这 307 行要么进不来，要么得编个假数字 —— 两条路都把数据搞脏。

**3. 为什么 `description` 用 `LONGTEXT` 而不是 `TEXT`？**

实测 `description` 最长 **28319 个字符**，而 `TEXT` 上限是 **65535 字节**。UTF-8 下一个中文占 3 字节，28319 字符早就超了 —— 用 `TEXT` 会被**静默截断**：MySQL 不报错，只是把多余的部分砍掉。这是最坏的一种错法，因为你看不出来。

**4. 为什么字符集是 `utf8mb4`？**

MySQL 里那个老的叫 `utf8` 的其实**只有 3 字节**（真名 `utf8mb3`），存不了 emoji 和一部分生僻字。**`utf8mb4` 才是真正完整的 UTF-8。**

**5. 为什么引擎必须是 `InnoDB`？**

只有 InnoDB 支持**外键和事务**。如果用 MyISAM，我写的**整个外键声明会被 MySQL 默默忽略** —— 不报错，但约束根本没立住。所以验证外键必须查 `INFORMATION_SCHEMA`，不能只看建表成功。

**6. `_id` 命名约定**

主键统一叫 `<表名>_id`：`jobs.job_id`、`companies.company_id`。这样外键一眼能看出指向哪张表。
