### curl命令

curl = 在命令行里发一个http请求，然后把响应打印出来，它是"浏览器减去界面"

```text
浏览器：发 HTTP 请求，渲染成网页，有界面
curl：  发 HTTP 请求，把响应原样吐到终端
```

```powershell
curl.exe -X POST https://api.example.com/jobs `
  -H "Content-Type: application/json" `
  -d '{"title":"Python开发"}'
```

常用选项：

- `-o`：决定把响应回来的东西往哪放，`curl.exe -o a.js https://...` 写进 a.js
- `-X`：指定这次请求用哪个 HTTP 方法(GET,POST,PUT,PATCH,DELETE)，不加 `-X` 默认是 GET
- 还有其他选项用法不一一举例，可以用 `curl.exe --help` 查看

它实际发出去的就是这个：

```text
POST /jobs HTTP/1.1                        ← -X POST  +  URL
Host: api.example.com                      ← 从 URL 里拆的(请求头)
Content-Type: application/json             ← -请求头
                                           ← 空行(分界)
{"title":"Python开发"}                      ← -请求体
```

## 复习一下HTTP的内容

### 请求长什么样

```text
POST /jobs?debug=1 HTTP/1.1          ← ① 请求行：方法 + 路径?查询串 + 版本
Host: 127.0.0.1:8000   (Host:主机号 = 网络号 + 端口号)       ┐
Content-Type: application/json                             │ ② 请求头（元信息）
Authorization: Bearer xxxxx                                ┘
                                     ← ③ 空行（必须有，分界线）
{"title": "测试岗"}                   ← ④ 请求体（可选，可以没有）
```

### 响应长什么样

```text
HTTP/1.1 201 Created                 ← ① 状态行：版本 + 状态码 + 说明
content-type: application/json       ┐
content-length: 109                  │ ② 响应头
date: Wed, 14 Oct 2026 07:17:08 GMT  │
server: uvicorn                      ┘
                                     ← ③ 空行
{"id": 5, "title": "测试岗"}          ← ④ 响应体
```

### HTTP方法

- GET 取/查询  没有请求体body  有幂等
- POST  创建    有请求体body   没有幂等
- PUT 整体替换  有请求体body    有幂等
- PATCH  局部修改  有请求体body   没有幂等
- DELETE  删除    一般没有body    有幂等

幂等就是： 同样的请求发 10 次，结果和发 1 次一样。

### 状态码

记住一条：4 开头怪客户端，5 开头怪服务器

```text
2xx：成功 ： 200 OK(查)，201 Created(建)
3xx: 重定向 ：301 永久/ 302临时 / 304 走缓存
4xx :客户端的错 ，404找不到 ， 422校验失败，400参数错误，401没登陆，403没权限
5xx : 服务器的错 ： 500代码炸了 ，502网关挂了
```

### URL的结构

```text
https://career.hebut.edu.cn/correcruit/content/id/81451?tab=1#comments
└─┬─┘   └────────┬────────┘└────────────┬────────────┘└──┬─┘└───┬───┘
 协议          主机名                  路径             查询串   片段
```

```text
协议：HTTP/HTTPS
主机名：要找哪台机器(DNS解析成IP)
端口：服务器机器上的哪个进程程序，http默认80 / https默认443 ，在fastapi中对应是--port
路径：要找的资源
```

### 常见的头

```text
Content-Type :声明这份 body 是什么格式
请求里：Content-Type: application/json → 我发的是 JSON
响应里：Content-Type: text/html; charset=utf-8 → 我回的是 HTML，UTF-8 编码
```

```text
Host :HTTP/1.1 必填。同一 IP 上跑多个网站时靠它区分
Authorization ：份凭证，如 Bearer <token>
User-Agent ：  我是谁（浏览器？curl？）
Content-Length：body 有多长
Server ：我是什么服务器(uvicorn)
```

## 无状态(最重要的一个)

HTTP 本身不记忆任何东西。 每个请求都是独立的，服务器不知道这个请求和上一个来自同一个人。

**为什么这么设计**：简单、好扩展（任何一台服务器都能处理任何一个请求，不用"粘"住某个用户）

**代价**：登录状态、购物车、**对话历史** —— 这些都需要"记住上次"

**怎么办**：每次请求自带凭证。有两条路 —— **Cookie** 和 **Token**。
它俩的差别**不在格式，在"状态存在哪"**。

```text
Cookie：浏览器替你拎行李
token： 你自己拎行李
```

---

### Cookie（配套的是 Session，属于"有状态"）

Cookie 是 **HTTP 协议自带**的机制，靠两个头工作：

```
① 登录时，服务器"下发"（Set-Cookie 是【响应头】）
POST /login  {"user":"hp","pwd":"***"}
        ←── 200 OK
            Set-Cookie: session_id=abc123; Path=/; HttpOnly

② 之后每个请求，浏览器"自动带上"（Cookie 是【请求头】）
GET /jobs
Cookie: session_id=abc123        ← 这行不是你写的，是浏览器加的
```

核心特征：**自动**。只要**域名和路径匹配**，浏览器就自动塞进去，前端什么都不用做。

#### Cookie 里存的不是"你的信息" —— Session

```
Cookie 里：  session_id=abc123                     ← 只是个随机串，本身没含义
服务器里：   {abc123: {user:"hp", role:"admin"}}    ← 真正的数据在这（内存或数据库）
```

服务器拿到 abc123 → 去自己的存储里**查表** → 知道你是谁。

```
浏览器                          服务器
Cookie: abc123   ──────>       查表 {abc123: {...}}
                               └─ 找到了，是 hp
```

这套做法叫 **Session**，也就是"**有状态**"：服务器**存了**东西。

| ✅ 优点 | ❌ 缺点 |
|---|---|
| 浏览器自动带，前端省事 | **服务器要存** —— 多台机器要共享（得上 Redis） |
| 能**随时踢人**：删掉 session 记录立即失效 | **跨域很麻烦** —— CORS + SameSite + credentials 三处都得配 |
| 数据在服务器上，改不了 | **只对浏览器有效**（curl / App 不管用） |

---

### Token（JWT，属于"无状态"）

服务器**签发**一个 token 给你，你自己保存，每次请求**手动**放在 Authorization 头里：

```
① 登录时，服务器"签发"
POST /login  {"user":"hp","pwd":"***"}
        ←── 200 OK
            {"token": "eyJhbGciOiJIUzI1NiJ9.eyJ1c2VyIjoiaHAifQ.xxxx"}

② 之后每个请求，你自己带
GET /jobs
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...   ← 手写，浏览器不会帮你加
```

核心特征：**手动，且跟浏览器无关**。

#### JWT 的结构

最常见的 token 格式叫 **JWT**，三截用 `.` 隔开：

```
eyJhbGciOiJIUzI1NiJ9 . eyJ1c2VyIjoiaHAiLCJleHAiOjE3MzAwfQ . SflKxwRJSMeKKF2QT4
└──── Header ────┘   └──────── Payload 载荷 ────────────┘   └─── 签名 ───┘
   用什么算法签名          装了什么数据（用户id、过期时间）      防止被篡改
```

⚠️ **关键点：Payload 是 base64 编码，不是加密！**

任何人都能解开看到里面写了什么。**base64 ≈ 给字符串换了个字体，不是上锁** ——
它看起来是乱码，但随便找个在线工具就能解出 `{"user":"hp"}`。

所以 **绝对不要往 Payload 里放密码、身份证号这类东西**。

在签发token的时候header的base64字符串 + "." +Payload的base64字符串 和密钥SECRET做混合得到每人对应的token的签名，下次你再次发起请求的时候你带着你的token，服务器会用密钥和你的"header的base64字符串 + "." +Payload的base64字符串"混合出来的字符串是不是 == 你请求头的token中的签名，相同就放行

#### 服务器怎么验？（不查表，只验签）

```
收到 token
  → 拿自己的密钥重新算一遍签名
  → 算出来跟 token 里带的签名一样吗？
      一样   → 没被改过 → 信里面写的内容
      不一样 → 被改过   → 401
```

**无状态。** 服务器不需要存储，任何一台机器都能独立验证。

---

### 核心对比

| | Cookie + Session | Token (JWT) |
|---|---|---|
| 数据存在哪 | **服务器** | **token 自己身上** |
| 服务器要存东西吗 | **要** | **不要** |
| 谁发出去 | **浏览器自动** | **你手写** |
| 跨域 | 麻烦 | 简单（放头里就行） |
| 能随时踢人吗 | ✅ 删记录立即失效 | ❌ 签出去就一直有效到过期 |
| 能被谁用 | 只有浏览器 | curl / App / 小程序 / 脚本，**谁都能用** |
| 适合 | 传统网站 | **前后端分离 / API** |

一句话记住本质：

> **Cookie = 浏览器帮你拎行李**（自动、但只在浏览器里、跨域受限）
>
> **Token = 你自己拎行李**（手动、但走遍天下、谁都认）

---

### 为什么现代 API 都选 Token

**① 跨域** —— 前端跑 `localhost:5173`，后端跑 `localhost:8000`，**这是两个域**。Cookie 要跨域得同时配：

- 后端 CORS 的 `allow_credentials=True` + 明确列出前端域名
- 前端请求的 `credentials: "include"`
- Cookie 的 `SameSite=None; Secure`（还得上 HTTPS）

**三处都不能错，错一处就静默失效。** Token 放 header 里，这些全都不用管。

**② 多端** —— Web、小程序、手机 App 都调同一个后端。**Cookie 是浏览器专属概念**，App 里根本没这回事。Token 谁都认。

**③ 无状态好扩展** —— 服务器不存 session，加机器就完事，不用考虑"我的 session 在哪台机器上"。

---

## fastapi的pydantic模型

Pydantic 描述请求体长什么样的

定义的类要继承BaseModel，这个类才变成Pydantic模型

```python
from pydantic import BaseModel,Field

class JobIn(BaseModel):
  title:str = Field(...,min_length=1)
  company: str
  region: str
  edu: str
  salary_min :int = Field(...,ge = 0)
  salary_max :int = Field(...,ge = 0)
```

## fastapi接口实现

```python
@app.get("/jobs/{job_id}")
def get_job(job_id:int):
  for j in JOBS:
    if j["id"] == job_id:
      return j
  raise HTTPException(status_code=404, detail=f"没有 id={job_id}的岗位")
```

## HTTP的post方法实现

```python
@app.post("/jobs",status_code=201)
def create_job(job:JobIn):
  new = job.model_dump()
  new["id"] = max(j["id"] for j in JOBS) + 1
  JOBS.append(new)
  return new

@app.get("/health")
def health():
  return {"status":"ok"}
```

其中的model_dump()方法是把Pydantic对象转成dict字典
